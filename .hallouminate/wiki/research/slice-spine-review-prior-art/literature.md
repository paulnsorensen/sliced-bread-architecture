# Prior art for "architectural coherence review" (seam coherence review)

Research question: established names and key literature for a human+AI workflow that reviews module seams for duplicated/leaky logic and decides to pull complexity up, push it down, or redesign the seam.

## Terms of art (top 3-5, ranked by precision fit)

1. **Architecture conformance checking** — the closest formal SE-research name for "compare intended vs. actual module structure and flag drift." Root: Murphy & Notkin's reflexion models.
2. **Architectural erosion / architectural drift / architectural decay** — the failure mode this workflow catches; used interchangeably in the literature (drift = divergence in intent, erosion/decay = accumulated violations), often via a "design structure matrix" or dependency graph.
3. **Connascence** (Page-Jones / Weirich) — the vocabulary for _why_ a seam is leaky: names the specific coupling strength/degree/locality driving a "pull up / push down / redesign" decision.
4. **Deep modules / shallow modules, pull complexity downward** (Ousterhout) — the design-quality vocabulary for the "push down" resolution.
5. **Fitness functions** (Ford/Parsons/Kua) — the closest name for making the review's pass/fail criteria executable and repeatable rather than one-off.

No single established term names the exact composite workflow (human + AI sidecar, whole-codebase seam sweep, three-way disposition). It sits at the intersection of architecture conformance checking + code-smell/refactoring review + (new) LLM-assisted architecture recovery.
