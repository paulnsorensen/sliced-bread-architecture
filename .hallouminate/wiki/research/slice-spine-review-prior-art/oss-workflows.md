# Prior art: hierarchical repo comprehension via per-file fan-out (architectural coherence review)

Research question: find OSS agent workflows that fan out over files/modules to comprehend a repo, and any prior art for extracting behavior assertions from tests as first-class specs, in service of a "human in IDE + AI sidecar" architectural coherence review workflow.

## Synthesis / verdict (3 lines)

No OSS project found does the specific thing this workflow needs: per-file/per-module LLM fan-out that (a) summarizes each file **and** its test file as a behavior-assertion pair, then (b) reviews the seams between modules for duplicated/leaky logic. <certain — based on the sources actually fetched below>

The closest pieces are split across three different projects and would need composing: RepoAgent's bottom-up per-object fan-out mechanism (dependency-ordered LLM calls) + Aider's repo-map for cheap seam/coupling signal without LLM cost + mikewolfd's `semi-formal-architecture-review`'s seam vocabulary and finding structure — but note that skill explicitly declines to use tests as evidence at the decision-review level, so its "seam" concept would need to be re-grounded in code-level module boundaries rather than ADR-level ones. <certain>

The "summarize what tests guarantee, per module" step is the biggest open gap: BDD living-documentation tools (Pickles/Concordion/SpecFlow+ LivingDoc) solve an adjacent but different problem (rendering human-authored Gherkin scenarios), and no LLM-based tool was found that infers behavior assertions from ordinary unit/integration test code and treats them as a first-class review input — this appears to be a genuinely uncovered niche, not just an under-search result. <speculating — absence claim, scope below>

## Open questions

- `josstei/argus-claude`'s actual cross-validation mechanism was not deep-read (low star count, time-boxed) — unconfirmed whether its "parallel analysis agents" fan out per-file or per-concern, and whether cross-validation includes seam/duplication detection.
- `RepoSwarm` (robotpaper.ai writeup) surfaced as a related "crawl all your repos, generate architecture docs via Claude Code SDK" tool but was not verified against its own repo (only a third-party blog was read) — flag as unconfirmed if it becomes relevant later.
- Whether academic literature (beyond the arXiv papers surfaced by general search) has a named technique for "test-derived behavior specification extraction" was not checked via a dedicated academic search (e.g., Semantic Scholar/arXiv search API) — Tavily's general web search may under-index papers behind that specific phrasing.
- `gh search code` for "seam" / "boundary" scoped to wshobson/agents returned no hits before hitting GitHub's rate limit (5,000/hr shared) — the search was not completed; wshobson/agents (38,858★, largest multi-harness agent catalog found) was not directly confirmed to lack seam-analysis content, only that a narrow code-search query found nothing before the limit hit. Worth a follow-up gh code search once the rate limit resets.

## Confidence

Overall: **certain** on what was fetched and read directly (RepoAgent, PocketFlow, deepwiki-open, Aider repo-map, repomix/gitingest, the two named Claude Code subagent specs, mikewolfd's skill file); **speculating** on the negative claim that no LLM-based "test behavior extraction" tool exists, since that rests on absence-of-hits from a bounded set of Tavily queries plus a rate-limited gh search — a dedicated academic-literature search or a broader gh code search (once rate limit resets) could still surface something. wshobson/agents' internals were not fully searched due to the GitHub API rate limit hit mid-session.
