### ADR-001: Entry points are a top-level layer; only the composition root imports adapters [status: accepted]

- **Context:** The dependency quick-check permitted `app/ → domains/*`, `adapters/ → domains/*`, and `domains/* → domains/common/`, and forbade `domains/* → adapters/`, `domains/* → app/`, `adapters/* → app/`, and `common/ → sibling domains`. Read as exhaustive, that set makes a composition root unrepresentable — no layer may legally instantiate a concrete adapter and inject it — and the blanket `adapters/* → app/` ban conflates driven adapters with driving ones, leaving HTTP servers, CLIs, schedulers, and message consumers with no legal home. Cockburn's own formulation and Cosmic Python's verified repo layout both split the two: primary/driving adapters call the application, secondary/driven adapters implement ports the application defines.
- **Decision:** `entrypoints/` becomes a top-level layer holding driving adapters, one per medium. `app/` holds use cases plus the composition root, and **only the composition-root module** (`app/bootstrap`, `main`) may import concrete adapters. `adapters/` means driven adapters exclusively. Nothing imports `entrypoints/`. The name is the reference for a role — Go `cmd/`, .NET `Web`/`API` satisfy it — because the doctrine is language-agnostic and the sibling crust rule already takes the language-native-form position. The use-case discriminator: a sibling slice may be imported directly for in-process queries and calculations; needing an entrypoint or a gateway makes the operation a use case wired at `app/`.
- **Alternatives:** (a) Let all of `app/` import adapters — simpler to state and grade, but a use case could depend directly on a concrete HTTP client and still pass every check, which is precisely the coupling model purity exists to prevent one layer down. (b) Mandate the literal string `entrypoints/` — unambiguous for tooling, but would file findings against idiomatic Go and .NET layouts where the convention is enforced or entrenched. (c) Split `adapters/` into `driving/` and `driven/` subdirectories — raised by the research but not independently verified, and it keeps driving adapters importable, losing the imported-by-nobody invariant.
- **Consequences:** The doctrine can now describe a real, wireable application. The audit gains a gradeable rule it could not previously express (adapter imported outside the composition root, medium). Cost: a fourth layer to teach, and the arrows-describe-direction-not-required-directories caveat must be explicit or the audit will file findings against repos that legitimately have no `entrypoints/`. The `SLICE_MAP_SCHEMA` kind enum gains `entrypoint` so mapped entry points are not silently classified `other`.
