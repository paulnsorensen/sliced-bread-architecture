### ADR-002: Cycle-breaking events live in common/; event machinery is staged and exempt from premature-abstraction findings [status: accepted]

- **Context:** Two defects met here. First, the doctrine's cycle remedy offered two placements for the breaking event — `common/events` **or** the emitting slice's public API — but the second does not break the cycle: if `pricing` must import `orders` for the event type while `orders` still imports `pricing` for totals, the module-level cycle survives, an import-time hazard in Python and in TypeScript barrels alike. Second, following the doctrine's own rule 5 immediately triggered a rule 4 finding: both tools grade "an event bus with one event" as premature abstraction, and the first cycle you break produces exactly one event plus dispatch machinery. The reference's original phrasing ("EventBus _interface_ when only one event exists") carried a saving nuance that both tools dropped.
- **Decision:** Cycle-breaking events live in `common/`, and the emitting-slice placement is no longer offered as an equivalent for that case. Machinery is staged: use a framework-native publisher directly when the framework provides one; otherwise the domain defines a publish port and a minimal in-process dispatcher owned by `app/` implements it; durability and delivery-guarantee concerns enter only when delivery leaves the process. A dispatcher introduced to break a cross-slice cycle is not premature abstraction, even with one event and one subscriber — this exemption ships inside the canonical growth-guards block, so every consumer carries it. The wrap-what-you-do-not-control rule is scoped to external dependencies and explicitly does not extend to a framework's own event publisher.
- **Alternatives:** (a) Keep both event placements with a caveat — rejected: the caveat would have to say "except in the case this section is about". (b) Require a wrapper around framework-native publishers on dependency-inversion grounds — rejected on evidence: Spring Modulith's own reference code calls `ApplicationEventPublisher` directly, and the only pro-wrapping source found was blog-tier. (c) Trigger the dispatcher on a count (second event, second handler) rather than on the structural need — no cited source states a numeric threshold, so it would be invented precision.
- **Consequences:** The doctrine stops contradicting itself at the exact point a reader first applies it, and the staged model matches what Spring Modulith, Cosmic Python, and kgrzybek's ADR 0015 independently document. Cost: `common/` accumulates event types, which the "not common: anything used by only one slice" rule would otherwise discourage — cycle-breaking events are a stated exception to it. Unresolved in the sources and left open: whether in-process durability is warranted before anything crosses a process boundary (kgrzybek writes an outbox record per event; microservices.io scopes the pattern strictly to the dual-write problem).
