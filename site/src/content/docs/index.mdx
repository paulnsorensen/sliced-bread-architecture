## The five rules

<CardGrid stagger>
  <Card title="Import direction" icon="right-arrow">
    Arrows point in a permitted direction: `entrypoints/` → `app/` → `domains/*` →
    `domains/common/`, plus `app/bootstrap` → `adapters/`. A slice may import a sibling slice's
    public API directly. Only the composition root imports concrete adapters, and nothing imports
    `entrypoints/`.
  </Card>
  <Card title="Crust integrity" icon="padlock">
    External consumers use a slice's public seam in the language's native form — exported
    identifiers, a package `__init__`, an index module. Internals can be renamed, split, or
    reorganized freely.
  </Card>
  <Card title="Model purity" icon="approve-check">
    Domain code imports stdlib, `common/`, and sibling public APIs. Infrastructure hides behind
    ports the domain defines and adapters implement.
  </Card>
  <Card title="Growth justification" icon="code-branch">
    Every directory and abstraction has 2+ concrete uses. One file → extract siblings → facade +
    folder. Numeric triggers are advisory signals that prompt a look, not gradeable thresholds.
  </Card>
  <Card title="Event usage" icon="rocket">
    Events resolve reverse dependencies — B reacts to A without A knowing B. They are not
    general-purpose messaging.
  </Card>
</CardGrid>
